# Regulatory Content Policy

## Source hierarchy
Official regulator/standard-setter sources are authoritative. Secondary sources may explain context but never replace the primary citation for a rule.

## Required metadata
Every jurisdiction rule must have: authority, jurisdiction, status, source URL, publication date, effective date if applicable, version, source locator, canonical concept mapping, reviewer status.

## Publication workflow
Draft -> automated checks -> primary SME review -> calculation/test verification -> editorial/localization review -> approval -> publish.

## Change workflow
Monitor sources -> create change candidate -> compare versions -> mark affected concepts/lessons/tools/tests -> SME review -> update/re-render affected segments -> regression/evals -> publish new version -> notify affected learners.

## Proposed rules
Render visually distinct from effective rules. Store proposal/comment/final/effective states explicitly.
